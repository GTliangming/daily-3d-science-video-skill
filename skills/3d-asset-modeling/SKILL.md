# 3D Asset & Modeling Skill

## 1. 职责与边界

把已批准的科学分镜和场景设计转化为**可用、可控、可复用、来源清楚**的 3D 模型资产。核心目标不是追求模型数量，而是让每个镜头都有正确且足够精细的模型。

- 主 Skill 负责科学核验、脚本和分镜批准。
- 场景 Skill 负责空间布局与对象关系。
- 本 Skill 负责资产需求拆解、素材来源评估、建模规范、模型检查和资产管理。
- 镜头 Skill 决定模型在镜头中的可见细节与构图。
- 灯光材质 Skill 负责最终表面外观；动画 Skill 负责模型的运动和机构。
- 不根据想象补齐未知产品结构。未知结构标记待核实，或使用明确标注的原理示意模型。

## 2. 先判断：下载、改造还是自己建模

不要默认所有东西都自己建，也不要为了省时间直接下载第一个看起来相似的模型。逐个资产做判断：

| 情况 | 推荐方式 | 判断依据 |
|---|---|---|
| 普通背景道具（桌椅、植物、房间装饰） | 下载/资产库 | 不承载科学信息，外观要求可控即可 |
| 常见环境、HDRI、纹理 | 下载 | 重点检查授权、分辨率和风格一致性 |
| 产品外壳且有准确参考图 | 下载后改造或自己建 | 轮廓、按钮、接口、比例需要匹配 |
| 产品内部关键部件 | 自己建模或严格改造 | 结构、数量、连接关系必须经过核验 |
| 需要拆解、旋转或剖切的模型 | 优先自己建/拆分 | 必须有独立部件、正确原点和可控层级 |
| 远景、短暂出现的非关键物体 | 简化模型或 AI 辅助 | 细节不值得投入高成本 |
| 主体特写、微距镜头 | 高质量定制模型 | 轮廓、倒角、法线、纹理和细节会被放大 |

### 决策原则

1. **科学关键性**优先于外观相似度：模型看起来像，不代表内部结构正确。
2. **镜头可见性**决定精度：微距主体需要高精度；背景模型可简化。
3. **动画需求**决定拆分程度：静态展示可以合并；需要运动的部件必须独立。
4. **修改成本**决定是否复用：下载模型若清理、重拓扑、拆件成本过高，就重新建模。
5. **授权可用性**是硬门槛：无法确认许可的资产不得进入商业发布成片。

## 3. 资产需求拆解流程

每个主题先建立资产清单，不要直接开始建模。

### Step 1 — 从分镜反推资产
按镜头列出：
- 主体产品/人物
- 需要单独运动或拆解的部件
- 辅助道具与环境
- 需要局部放大、剖切或爆炸图的结构
- 需要展示的表面细节
- 参考图/尺寸/结构事实来源

### Step 2 — 标注重要程度
每项标记：
- **A 科学关键**：部件结构、数量、连接、功能和运动需核验。
- **B 视觉主体**：外观、轮廓、材质和比例需要较高还原度。
- **C 环境辅助**：允许用通用模型或简化资产。
- **D 装饰背景**：只要不抢焦点且不误导即可。

### Step 3 — 定义资产规格
每个模型至少写清：
- Asset ID / 中文名称 / 类别
- 真实参考来源与适用型号
- 目标镜头、景别和最终画面尺寸
- 目标尺寸、单位和比例依据
- 静态/可动画/可拆解/可剖切
- 必须独立的部件
- 目标细节等级与允许简化项
- 目标交付格式、纹理要求和授权要求

## 4. 资产来源与授权核验

可考虑的来源类型：
- **用户或制造商资料**：产品照片、说明书、维修手册、官方结构图；用于核验产品外观和结构。
- **Sketchfab 等模型社区/市场**：适合查找具体产品、设备和道具模型；逐个检查模型页面的许可与下载条件。
- **BlenderKit 等 Blender 资产库**：适合场景道具、材质和通用模型；核对每项资产的授权层级。
- **Poly Haven、ambientCG 等资源库**：可用于环境纹理、HDRI 和材质；仍需保存具体资产的来源和许可记录。
- **自建模型**：当结构准确性、拆件或镜头质量无法由现成资产满足时采用。

### 每个资产都必须记录

- 来源平台和原始页面 URL
- 作者/创作者（若有）
- 资产名称、版本和下载日期
- 页面明确标注的许可证名称及许可证链接
- 是否允许商业使用
- 是否允许修改/衍生
- 是否要求署名，以及署名文本
- 是否有再分发、嵌入或其他限制
- 原始文件与下载文件的保存位置

**不能把平台整体政策当成单个模型的许可证。** 同一平台不同模型可能采用不同授权。不能因为可免费下载就认定可以商用，也不能把“署名即可”当成所有授权的通用规则。许可证不明、页面信息冲突或作者未授权时，标记为 BLOCKED，不进入最终成片。必要时联系作者或改用自建/明确授权的替代资产。

仓库中的资产登记模板只记录元数据，不自动授予任何使用权。对商业发布项目，应保存下载时的许可页面截图或文本存档，并按发布平台/客户合同要求复核。

## 5. 模型质量检查

### 几何与拓扑
- 检查非流形边、重复面、内部多余几何、破面和异常法线。
- 检查薄片、缝隙、交叠和穿插；产品外壳接缝应有明确设计。
- 对近景产品控制轮廓质量、倒角宽度和曲面连续性。
- 只有在变形、细分或后续编辑需要时才投入重拓扑；静态背景资产不必盲目追求四边面。
- 不以面数作为唯一质量标准，按最终像素尺寸、镜头距离和运动需求确定细节。

### 比例、单位与原点
- 项目统一使用米制单位，并在项目设置中记录 Unit Scale。
- 真实尺寸优先取自可靠尺寸资料；没有尺寸时标注估算，不伪装成实测。
- 模型导入后检查朝向、尺度、原点和轴向。
- 可动画部件的 Origin 必须位于正确旋转/运动轴或连接点。
- 建立清楚的父子层级，避免通过任意负缩放修正方向。
- 应用或保留变换要有明确理由；动画、修改器和导出前检查变换状态。

### UV、材质与纹理
- 近景主体需要合理 UV，避免拉伸、重叠错误和接缝落在明显区域。
- 记录纹理分辨率、色彩空间和贴图类型。
- Base Color 等颜色贴图按色彩贴图管理；Normal、Roughness、Metallic 等数据贴图按非颜色数据处理。
- 纹理分辨率按镜头覆盖像素确定，不要所有模型都使用超高分辨率。
- 贴图文件采用相对路径并检查打包/交付完整性。

### 动画与拆件准备
- 需要爆炸图或机构运动的部件必须单独对象或有明确可控分组。
- 部件命名稳定；记录父对象、旋转轴、运动范围和装配位置。
- 检查连接处是否有隐藏缝隙、穿插或错误间距。
- 若需要角色动画，检查骨架、权重、动作来源和许可；不适用时不要为了“完整”强行加 Rig。

## 6. Blender 资产组织与交付

建议项目目录：
```text
project/
  assets/
    models/source/          # 原始下载/采购文件，只读归档
    models/working/         # 清理、拆件、改造中的工程文件
    models/final/           # 通过验收的最终模型
    textures/               # 贴图
    references/             # 参考图、尺寸图、许可存档
    licenses/               # 授权页面存档、署名要求
  scenes/
  renders/
  manifests/
    asset-register.json
```

建议 Collections：
- `ASSET_HERO_*`：主体产品
- `ASSET_PART_*`：独立部件
- `ASSET_PROP_*`：道具
- `ASSET_ENV_*`：环境资产
- `ASSET_RIG_*`：骨架与控制器
- `ASSET_GUIDE_*`：尺寸标尺、参考和辅助对象

推荐格式：
- **.blend**：Blender 原生工作文件，适合保留材质节点、修改器、层级、约束和动画。
- **.glb/.gltf**：适合交换网格、材质和部分场景数据；导入后仍需检查材质、坐标、动画支持和兼容性。
- **.fbx**：常用于网格、骨架和动画交换；检查单位、轴向、骨骼和材质转换。
- **.obj**：适合简单静态几何交换；通常不能完整保留复杂材质节点、Rig 和动画。
- 不要仅凭扩展名判断兼容性。记录来源软件、导出设置和目标 Blender 版本，导入后做实际检查。

### 命名规则
使用稳定英文 ID，避免重名：
- 对象：`OBJ_HairDryer_Body`
- 部件：`PART_Motor_Rotor`
- 材质：`MAT_Housing_MattePlastic`
- 贴图：`TEX_Housing_BaseColor_2K`
- Collection：`ASSET_HERO_HairDryer`

观众可见的标签、字幕、图注和语音仍必须为简体中文。

## 7. 建模与验收流程

1. 收集并标注参考资料。
2. 完成资产清单和授权检查。
3. 先制作低模/灰模，确认比例、轮廓、部件关系。
4. 关键科学结构经核验后，再进行高模细节。
5. 进行拓扑、法线、UV、材质和贴图检查。
6. 按镜头制作测试渲染，检查最终像素尺寸下的细节。
7. 对可动画资产检查 Origin、层级、碰撞和拆件。
8. 记录最终版本、来源、许可证和验收结果。
9. 通过验收后放入 final 目录；保留原始文件，不覆盖源资产。

## 8. 输出格式

按主题交付：
1. 资产清单（Asset ID、名称、类别、镜头、优先级）
2. 每项资产的来源方案：下载 / 改造 / 自建 / 暂缓
3. 参考资料与尺寸/结构依据
4. 资产授权登记状态
5. 建模规格：比例、细节等级、拆件、拓扑、UV
6. Blender 层级、命名、Origin 和单位要求
7. 文件格式与贴图交付规范
8. 镜头测试渲染要求
9. 风险、待核实项和验收结论

## 9. 中文与科学准确性

所有面向观众的旁白、对白、字幕、标题、标签和信息图均使用简体中文。旁白使用自然普通话，轻松、有趣、有故事感，允许适度幽默，但不能为了笑点改变科学结论。Blender 对象名、文件名和技术字段可用英文。

模型外观与内部结构必须区分：
- 真实产品外观：以指定型号或可靠参考为准。
- 内部结构：必须有证据；无证据时使用明确标注的“原理示意”。
- 艺术化细节：不得被描述为真实结构或真实参数。

## 10. 验收清单

- [ ] 每项资产都对应至少一个镜头或明确用途
- [ ] 关键结构、数量和比例有资料依据
- [ ] 已明确下载/改造/自建决策
- [ ] 来源 URL、作者和许可证信息完整
- [ ] 商业使用、修改和署名条件已核实
- [ ] 未授权或许可不明资产已阻止使用
- [ ] 模型尺度、轴向、原点和变换正确
- [ ] 几何、法线、拓扑和表面无明显错误
- [ ] UV、纹理路径、色彩空间和分辨率合理
- [ ] 动画部件独立且层级、旋转轴正确
- [ ] 最终模型在目标镜头中完成测试
- [ ] 资产源文件、最终文件和许可记录均已归档
- [ ] 面向观众的文字和声音符合中文规范
