# Reference Image Consistency Skill

## 1. 目标与适用时机

本 Skill 专门负责视频项目的参考图策划、提示词编写、外部生成指导和一致性验收。

在主视频 Skill 中，只有当脚本和分镜已确认、Visual Bible 已形成草案后才调用本 Skill。它不负责重新策划视频，也不替代科学事实核验、分镜设计或视频生成。

核心目标不是让所有图片长得一模一样，而是确保它们属于同一部影片：主体身份、结构、材质、灯光、色彩、渲染质感和摄影语言稳定，同时允许构图、景别和动作按镜头需求变化。

## 2. 核心原则

1. **先锁风格，再批量出图**：禁止一开始就为所有镜头分别写互不关联的文生图提示词。
2. **Visual Bible 是文字规范，主风格图是视觉锚点**：两者共同约束后续图片。
3. **主体一致性与风格一致性分开管理**：同一产品/角色的身份参考图，不一定能代表全片灯光和渲染风格；需要时分别提供主体参考和风格参考。
4. **科学结构优先**：机械连接、零件数量、相对位置、流体路径和运动关系必须来自已核验资料。不能为了画面好看而虚构结构。
5. **提示词必须自包含**：交给用户的每张图提示词都必须能单独复制使用，不依赖“沿用上文”“保持之前风格”等聊天上下文。
6. **尊重模型真实能力**：根据实际图片模型适配参考图、风格参考、主体参考、图生图强度、种子和负面提示词等参数。未知能力标记为待确认，不得臆造参数。
7. **生成与验收分离**：模型生成成功不等于参考图合格；必须经过人工确认和一致性检查。

## 3. 标准工作流

### 阶段 A：读取并整理 Visual Bible

先读取主 Skill 生成的 Visual Bible、已确认分镜和科学资料。将规范拆成以下锁定项：

- 项目风格 ID：项目内唯一，例如 `STYLE-001`。
- 视觉类型：写实电影级 3D 科普、产品广告级 3D、写实机械剖面等。
- 主体身份：名称、轮廓、比例、颜色、关键识别特征。
- 结构锁定：部件名称、数量、位置、连接关系、运动方向。
- 材质锁定：金属、塑料、橡胶、玻璃、液体等的表面特征。
- 色彩系统：主色、辅助色、背景色、特殊科学可视化颜色及其含义。
- 灯光系统：主光方向、补光、轮廓光、色温、对比度、阴影特征。
- 摄影与构图：镜头质感、透视、景深、画面比例和常用视角。
- 环境规范：背景、地面、道具、空间氛围。
- 禁止项：卡通化、低多边形、塑料玩具感、错误结构、随机文字、水印等。

如果关键字段缺失，先补充建议并请用户确认，不要直接批量生成。

### 阶段 B：建立三层参考体系

按需建立三种参考图，不要把所有作用混为一张图：

1. **风格锚点（Style Anchor）**：展示最终成片的渲染质感、灯光、色彩、背景和摄影风格。它回答“这部片子看起来是什么样”。
2. **主体锚点（Subject Anchor）**：展示同一个产品、机械、角色或生物的标准外观、比例、颜色和识别特征。它回答“画面里始终是谁/是什么”。
3. **结构锚点（Structure Anchor）**：展示经过核验的内部结构、零件关系、剖面或关键局部。它回答“内部真实结构是什么”。

一个项目可以复用同一张图承担多个作用，但必须在映射表中说明用途。对于复杂机械，通常建议风格锚点、主体锚点和结构锚点分开。

### 阶段 C：先生成并确认主风格参考图

1. 根据 Visual Bible 编写一份主风格参考图提示词。
2. 主风格图优先选择能代表全片材质、光影、背景和渲染质量的典型主体画面。
3. 不要在主风格图中塞入过多复杂动作、文字标签或多个无关主体。
4. 将主风格图交给用户在其可用图片工具中生成；若当前环境有图像生成能力且用户授权本次生成，可直接生成。
5. 用户确认后记录：
   - 状态：`STYLE_REFERENCE_APPROVED`
   - 文件名/图片编号
   - 图片用途
   - 确认日期或项目版本
   - 不能改变的视觉特征
6. 未经用户确认，不得将草稿主风格图视为已锁定标准。

如果用户要求调整风格，先更新 Visual Bible，再重新生成/确认主风格图；检查哪些旧参考图受影响。

### 阶段 D：生成主体与结构锚点

主风格确认后，再生成主体标准图和关键结构图。

- 主体图优先保持标准视角、完整轮廓和清楚比例。
- 结构图优先保证结构可读、部件关系正确；必要时使用正交视图、剖切视图或爆炸图。
- 对机械内部结构，提示词必须明确“结构示意必须遵循已核验结构，不得自行增加/删除/移动零件”。
- 如果外部图片模型无法可靠表达精确机械结构，建议用 Blender/CAD/人工修图制作结构锚点，不要把生成模型的猜测当成真实结构。
- 主体图和结构图生成后，用户逐项确认并登记版本。

### 阶段 E：为每张参考图生成独立提示词

每张提示词按以下顺序组合：

1. 项目视觉锁定信息（从 Visual Bible 提取）。
2. 主风格锚点和主体/结构参考图的使用说明。
3. 本图唯一目标。
4. 主体、动作、视角、构图和环境细节。
5. 真实结构约束。
6. 输出规格（比例、方向、分辨率等，仅填写目标模型确实支持的参数）。
7. 负面提示词。
8. 生成后验收标准。

提示词文件必须包含完整文字，不可只写“使用全局风格提示词”。即使模型不支持上传参考图，也必须保留文字版风格锁定规范，并说明一致性只能尽力控制，无法保证。

#### 可复制提示词模板

```text
[PROJECT / STYLE LOCK]
Project: {项目名称}
Style ID: {STYLE-001}
Visual style: {从 Visual Bible 提取的完整风格描述}
Rendering: {渲染质感、真实程度、细节等级}
Lighting: {固定灯光方向、色温、对比度}
Color system: {固定主色、辅助色、背景色及特殊颜色语义}
Materials: {主体与关键部件的材质表现}
Environment: {全片环境和背景规范}
Camera language: {摄影质感、透视和景深规范}

[REFERENCE INPUTS]
Style reference: {文件名/编号；用于控制风格}
Subject reference: {文件名/编号；用于控制主体身份}
Structure reference: {文件名/编号；用于控制结构；如不需要写明原因}
Reference priority: {说明哪张图控制什么，发生冲突时以何者为准}

[THIS IMAGE]
Image ID: {REF-xxx}
Purpose: {本图唯一目的}
Subject: {主体与身份特征}
Structure: {需要展示的结构及准确关系}
Action / state: {静态状态或动作}
Camera / composition: {视角、景别、主体位置、构图}
Background: {本图场景}
Allowed variations: {允许变化的内容}
Must remain unchanged: {不可变化的内容}

[SCIENTIFIC / DESIGN CONSTRAINTS]
{已核验事实与结构限制；不得自行补全未知结构}

[OUTPUT]
{目标图片比例、方向、分辨率等模型支持参数}

[NEGATIVE]
{统一负面约束 + 本图特有负面约束}
```

不要机械地把同一段英文堆到每张提示词里。应将 Visual Bible 的具体值转成清晰、无冲突的描述；若目标模型对英文理解更好，可将技术描述写成英文，但交付给用户时说明其含义。

### 阶段 F：批次生成与一致性验收

推荐批次：

- 第 1 批：风格锚点。
- 第 2 批：主体锚点与结构锚点。
- 第 3 批：场景、材质和关键镜头参考图。
- 第 4 批：其余分镜参考图。

每批生成后先检查再继续。验收维度：

| 维度 | 检查内容 |
|---|---|
| 风格 | 是否与已确认主风格图的渲染质感一致 |
| 主体 | 轮廓、比例、颜色、识别特征是否一致 |
| 结构 | 部件数量、连接关系、位置和运动逻辑是否正确 |
| 材质 | 金属、塑料、橡胶、玻璃、液体是否表现统一 |
| 灯光 | 主光方向、色温、对比度和阴影是否一致 |
| 色彩 | 主色、辅助色和特殊视觉编码是否漂移 |
| 环境 | 背景、空间氛围和道具是否符合规范 |
| 构图 | 是否满足该镜头叙事目的，且不破坏连续性 |
| 瑕疵 | 是否有畸变、重复零件、伪文字、水印或不合理细节 |

每张图标记：待生成 / 已生成待审 / 已通过 / 需重做 / 已弃用。只有用户确认或明确授权自动验收后通过的图片，才能进入最终参考图映射表。

### 阶段 G：处理不一致与版本变更

发现不一致时，先判断问题类型：

- 风格漂移：重新引用风格锚点，调整提示词或图生图方式。
- 主体漂移：重新引用主体锚点，明确不可改变的轮廓和比例。
- 结构错误：回到事实核验和结构锚点，不要只靠增加形容词修补。
- 构图不合适：只调整当前图的镜头和构图描述，保留全局锁定信息。
- 模型能力不足：改用支持参考图的模型，或使用 Blender/CAD/后期修图。

Visual Bible 或主风格图版本变化时，建立变更记录，并列出受影响的图片编号。不得静默覆盖已经确认的参考图。

## 4. 模型能力适配规则

开始输出提示词前，先确认用户将在哪个图片工具中生成，或允许先提供通用版本。

根据工具实际能力选择策略：

- 支持风格参考：将风格锚点作为风格输入。
- 支持主体/角色参考：将主体锚点作为身份输入。
- 支持多参考图：分别指定风格、主体、结构参考及优先级。
- 只支持单参考图：优先选择对当前镜头最重要的参考图，并在提示词中补足其他约束。
- 支持图生图但没有专门参考类型：明确说明输入图是构图/内容/风格的哪一种引导，避免把强度参数写成通用值。
- 不支持参考图：只用完整文字规范，明确一致性控制能力有限。
- 支持固定 seed：可以记录并在同一模型、相同参数条件下复用；不得承诺 seed 能锁定主体或保证跨版本一致。
- 支持负面提示词：单独输出；不支持时将关键限制改写为正向描述，并说明限制能力。

不要凭空填写模型参数、参考图权重、ControlNet 名称、LoRA、seed 或采样器。用户提供模型名称或工作流后，再按其能力精确适配。

## 5. 交付文件

每个项目至少交付：

- `03-visual-bible.md`：全片视觉规范及版本。
- `references/00-style-reference-prompt.md`：主风格图提示词。
- `references/01-subject-anchor-prompt.md`：主体锚点提示词。
- `references/02-structure-anchor-prompt.md`：结构锚点提示词（如适用）。
- `references/REF-xxx-prompt.md`：每张参考图独立提示词。
- `04-reference-image-map.md`：图片编号、文件名、用途、状态和适用镜头。
- `05-reference-image-qa.md`：验收结果和返工记录。

图片由外部工具生成时，交付的是提示词和文件组织方案，不得声称图片文件已经生成或保存。

## 6. 完成标准

在结束参考图阶段前确认：

1. Visual Bible 已确认并有版本号。
2. 主风格锚点已确认；若用户选择不生成，必须记录替代方案和风险。
3. 主体与结构锚点按项目需要准备完成。
4. 每张参考图都有独立完整提示词。
5. 每份提示词都明确说明参考图用途和允许变化/禁止变化内容。
6. 目标图片模型的能力与参数没有被臆测。
7. 图片映射表覆盖所有需要参考图的镜头。
8. 所有图片状态清楚，未通过的图片没有混入最终交付。
9. 用户清楚哪些图片需要在外部工具生成、审核和保存。

## 7. 与主 Skill 的边界

- 主 Skill 决定视频讲什么、脚本和分镜是什么。
- Visual Bible 定义全片视觉规则。
- 本 Skill 负责把规则转成参考图生成方案、独立提示词和验收机制。
- 3D 灯光与材质 Skill 负责更深入的物理材质和灯光制作参数。
- 3D 资产建模 Skill 负责真实资产获取、建模、拆件和授权。
- 视频模型 API、密钥、账号和真实调用由用户在 Skill 外部配置。

本 Skill 不承诺不同图片模型之间能够达到像素级一致。它通过规范、参考输入、分批生成和人工验收尽可能降低风格漂移。
