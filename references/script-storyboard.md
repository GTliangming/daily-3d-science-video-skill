# 脚本与分镜设计指南

## 1. 脚本结构

建议默认 2.5–4 分钟，围绕一个核心问题展开。

| 段落 | 目标 | 内容 |
|---|---|---|
| 开场钩子 | 留住观众 | 一个熟悉现象、疑问或反常识 |
| 建立问题 | 让观众知道要解释什么 | 生活场景、使用体验 |
| 结构介绍 | 建立空间认知 | 外观、剖切、关键部件 |
| 原理拆解 | 完成知识传递 | 按因果顺序逐步展示机制 |
| 回到生活 | 让知识有用 | 使用边界、安全提醒或常见误区 |
| 总结收束 | 强化记忆 | 一句话总结、互动问题 |

## 2. 旁白原则

- 默认以第三人称旁白作为主叙事线。
- 人物可以在生活场景中出现、观察、操作和交流；除非用户明确要求，不需要让人物对白承担核心知识讲解。
- 每句话尽量只传递一个信息点。
- 抽象术语先用生活语言解释，再给出术语。
- 避免“神奇黑科技”“瞬间改变分子结构”等无依据表达。
- 旁白必须与画面对应，不能出现画面展示 A、旁白却讲 B 的情况。

## 3. 脚本表格

| 时间 | 旁白 | 画面 | 屏幕文字 | 音效/音乐 | 科学依据 |

## 4. 分镜字段

每个镜头必须说明：
- 镜头编号、时长
- 景别：远景/中景/近景/特写/微距
- 机位与运动：推、拉、摇、移、环绕、跟拍、固定
- 主体与动作
- 环境、材质、光线
- 关键结构或物理过程
- 旁白、字幕、音效
- 实现方式：实拍 / AI 视频 / Blender 3D / 动态图形 / 素材
- 连贯性要求与负面约束

## 5. 镜头设计原则

1. 先让观众知道物体是什么、处于什么环境，再进入内部结构。
2. 外观镜头建立真实感，剖切镜头建立空间认知，过程动画解释原理。
3. 关键机制应有完整连续镜头，不要只靠快速闪切。
4. 复杂过程拆成多个易懂步骤，避免同时出现过多箭头、粒子和标签。
5. 同一物体跨镜头保持形状、颜色、部件位置和比例一致。
6. 镜头运动服务于信息表达，不为炫技而旋转。
7. 字幕只突出关键词，不逐字堆满屏幕。

## 6. 提示词组成

建议结构：
主体 + 动作/过程 + 场景 + 镜头/构图 + 光线 + 材质 + 视觉风格 + 连贯性约束 + 负面约束。

不要只写“cinematic, 8K, masterpiece”。要具体说明镜头里发生什么、观众应该看懂什么。

## 7. 旁白与画面检查

逐句检查：
- 这句话是否有对应画面？
- 画面是否真的支持旁白结论？
- 需要标注“示意图”吗？
- 观众能否在当前镜头时间内读懂字幕？
- 是否把多个知识点塞进一个镜头？
